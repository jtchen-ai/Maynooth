

# 传输层

## 传输服务和协议为在不同主机上运行的应用进程提供逻辑通信

- 发送端：传输层将应用层消息（从发送应用进程接收）转换为传输层数据包
  transport layer segments, 拆分为数据段后传递给网络层，段被封装在网络层数
  据包（称为数据报 datagram）中，并发送到目标。
- 接收端：网络层从数据报中提取传输层段，并将该段传递给传输层。传输层随后处
  理接收到的段，将数据段组装成消息，可供接收应用程序（应用层）使用。



网络层：主机之间的逻辑通信           传输层：进程之间的逻辑通信

**例子：**假如哆啦A 梦 要在家里给你的家人们写信，你负责分给你的家人们

家：主机              家人们：应用程序进程              信：应用消息              套接字：信箱

邮政服务：网络层协议              你负责分给你的家人们：传输层协议（TCP / UDP）



## **发送端的复用 Multiplexing**

- 从源主机的不同套接字收集数据块，用头部信息（稍后用于解复用）封装每个数据块
  （比特集合）以创建数据段，并将数据段传递给网络层

- **发送端的解复用 Demultiplexing**

  - TCP：在接收端，传输层检查这些字段以识别接收套接字（源/目的 IP+端口号，
    数据包），然后传输层将分段中的数据传递到正确套接字

  - UDP：在接收端，传输层仅检查数据段头部中的**目的端口号**，所有具有相同目的
    端口号的数据报都会被导向绑定该端口号的唯一套接字





## **UDP 用户数据报协议**User Datagram protocol

- 无需在数据传输前建立连接，不涉及握手，数据可能会丢失





- 校验和 checksum：
  - 将数据分为多个16位相加，然后取补码（最高位的进位要加到最末尾）





## **TCP 传输控制协议(Transfer Control Protocol)**

- 同一连接中同时进行双向数据流，握手，使用校验和，并通过重传尝试恢复丢失或损
  坏的数据包

- ACK：设置确认标志位

- SYN：同步标志位

- Seq ：序号

- FIN：结束标志位

- RST：异常处理位





## **三次握手**

- 样本往返时间（SampleRTT-S）：发送一个报文段到其确认 (ACK) 之间的时间

- 估计往返时间（EstimatedRTT-E）：对多个样本往返时间进行平滑处理后的平均值 

- 偏差往返时间（DevRTT-D）：测量样本往返时间与估计往返时间之间的差异程度 
- 公式：

​	E = (1 - α)*E + α*S                  (α = 0.125)

​	D = (1 - β)*D + β*|S - E|         (β = 0.25)

​	超时间隔TimeoutInterval = E + 4*D

​	4*D 在这里叫做安全边际safety margin







## **TCP重传 Retransmissions**

- 通过重传计时器触发重传**(**retransmission timer)
  1. TCP 段被发送，但 ACK 丢失因此重新发送另一份副本

  	2.收到 ACK ，但计时器错误地到期导致不必要的重传。

  	3.接收方使用累计确认 cumulative acknowledgement来表明它已成功接收到所有之前的数据。







## **TCP 快速重传 fast retransmit**

- 通过快速响应连续重复确认(ACK)指示的数据包丢失来增强传统的重传过程

- 超时周期通常相对较长
- 通过重复确认检测丢失的片段(发送方通常连续发送多个数据段，一般是3

​      A发送Seq = 92的报文段

1. B收到Seq = 92的报文段
2. A发送Seq = 100的报文段
3. B没有收到Seq = 100的报文段
4. 对于每一个 Seq =100 之后的报文段
5. Host B 都会发送 ACK = 100
6. 当 Host A 收到 第三个重复 ACK = 100
7. 它根据 快速重传 规则 进行重传，无需等待RTO到期

## **TCP关闭连接：四次挥手**

客户端发送 TCP 段，FIN 位=1；服务器对收到的 FIN 进行响应并发送 ACK

## **拥塞控制原理 Principles of congestion control**

- 来自太多源头的太多数据包存在，并且网络无法快速处理。主要有三种场景

- 无限缓冲区  Infinite Buffers

  - 数据包永远不会因为“满了”而被丢弃，所以没有丢包。

  - 当发送速率超过链路容量（即总速率 > R/2）时，多出来的数据包会无限期地堆
    积在缓冲区中排队。导致巨大的排队延迟 (Large Queuing Delay)



- 有限缓冲区与重传

  - 理想化情况： 假设发送方有“上帝视角”，知道什么时候路由器有空位。它只在
    有空位时发送。这种情况下没有丢包，吞吐量最高。

  - 次理想情况： 发送方不知道缓冲区状态，但知道哪个包丢了，只重传丢了的包。
    此时，为了获得λout的有效数据，发送方必须发送λin的数据（包含重传）。代价
    是：需要更多的输入带宽来维持同样的输出。 

  - 现实情况（重复发包/Duplicates）： 发送方不仅因为丢包而重传，还可能因为超
    时设置过短（premature timeout），在数据包其实还在排队（没丢）的时候就
    重传了。结果导致接收方收到了两份一样的数据包。吞吐量直线下降



- 多跳路径与上游浪费 (Multi-hop Paths)
  - 当一个数据包在快到终点时被丢弃，那么它之前经过的所有路由器所做的传输工
    作（Upstream transmission capacity）全部都白费了。
  - 比如一个包要走 5 跳，在第 4 跳因为拥塞被丢了。那么第 1、2、3 跳的带宽虽然被消
    耗了，但没有产生任何价值。这不仅影响了该数据包，还挤占了第 1、2、3 跳上其他
    本可以成功传输的数据包的资源。
