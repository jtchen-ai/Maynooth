# 链路层

## 定义

### 链路层负责在链路上将数据报从一个节点传输到物理相邻的节点

### 通过不同链路协议在不同链路上传输的数据报，每个链路协议提供不同的服务

## 链路层服务

### 帧同步

- 帧由一个数据字段和一个多个头部字段组成，网络层数据报文被插入数据字段中。

### 链路接入

- 共享介质中的信道接入，帧头中使用的“MAC”
（medium access control 介质访问控制）地址用于标识源和目的的唯一地址

### 相邻节点之间的可靠传输：

- 低比特错误链路

	- 光纤

	- 某些双绞线

- 无线链路

	- 高错误率

### 流程控制

- 在相邻的发送与接受节点之间行走

### 错误检测

- 接收器检测到错误的存在，发送请求重传或丢弃帧的信号

### 错误校正：

- 接收器识别并纠正位错误，无需重传

### 半双工和全双工

- 在半双工模式下，链路两端的节点可以传输，但不能同时进行

- 在全双工模式下，链路两端的节点可以同时传输

## 错误检测技术

### 奇偶校验 Parity Check：

- 添加一个额外的位,计算其中 1 的数量,然后进行偶校验或奇校验（如果是偶校验，1有偶数个，那就是1；反之成立。奇校验同理）

### 校验和  Checksum

- 将数据分成等大小的段（16 位）求和，最高有效位的进位需要加到结果中，最后求反码即为校验和

### 循环冗余校验 Cyclic Redundancy Check （CRC）

- 由发送方和接收方决定除数 L，在原消息后附加 L-1 位（零），执行二进制除法运算

- 例：原始数据/消息是 101110，除数为1001

- 得出余数为011（CRC）

- 因此，传输的数据是 101110011

## 错误检测

### EDC:

- 错误检测与纠正位(冗余)Error Detection and Correction bits (redundancy)

### D:

- 受错误检查保护的数据

### 协议可能会遗漏某些错误但很少见，更大的 EDC 字段能提供更好的检测和纠正

- 单比特错误：

	- 在一个帧中，只有一个比特，无论在何处，都是损坏的

- 多重位错误：

	- 帧接收时存在超过一位处于损坏状态

- 突发错误Burst error：

	- 帧包含超过 1 个连续位损坏

## 多路访问链路 Multiple access links

### 两种“链路”类型：

- 点对点 Point-to-point

- 广播（共享线缆或介质）Broadcast (shared wire or medium)

## MAC 协议：

### 信道划分 Channel partitionin 协议

- 时分多址 Time division multiple access（TDMA ）

	- 单信道上的传输时间被划分为不重叠的时间段

	- 来自不同源的信号被划分为相同大小的单元

	- 每个节点在每个轮次中获得固定长度的时隙（长度 = 数据包传输时间）

	- 未使用的时隙处于空闲状态

- 频分多址 Frequency division multiple access（FDMA）

	- 总带宽被划分为一系列不重叠的频率子带

	- 信道频谱划分为频带

	- 未使用的传输频率子带处于空闲状态

## 随机存取 Random acces 协议：ALOHA

### 定义

- 用于共享介质，在任何时候，从任何节点，都可以使用共享通信网络通道发送数据。

- 当多个系统在同一时间尝试在共享通信通道上传输数据时，就会导致冲突，丢帧

- 纯 ALOHA（无时隙）Pure (unslotted)

### 然后

- 节点在有任何数据要发送时就会传输帧。

- 当两个或多个节点同时传输帧时，会发生冲突，帧会被破坏。节点会等待一段随机的时间然后再次发送

## CSMA（载波侦听多路访问）carrier sense multiple access

### 定义

- 在传输任何数据之前会监听或感知载波/介质上的网络信号，

- 如果感知到信道空闲：发送整个帧 / 如果感知到信道忙碌：延迟传输

### 类别

- 持续型 Persistent：

	- 如果信道空闲，则立即发送数据。

- 非持续型Non-Persistent：

	- 如果信道不活跃，它立即发送数据，否则等待一个随机时间。

- P-持续型 P-Persistent：

	- 如果信道空闲，则以‘P’的概率发送帧，否则等待下一个时隙。

## “轮流”“Taking turns”协议

### 控制令牌按顺序（循环）从一个节点传递到下一个节点。节点只有在有数据要发送时才持有令牌——最多持续一段时间

### 如果令牌丢失，需要恢复程序

## 滑动窗口协议 Sliding Window

### 定义

- 发送端可以一次发送多个帧（不必等 ACK），接收端可以用一个 ACK 来确认多个帧，每个帧都有序号（sequence number）

### 流程

- 判断哪些帧丢失（例如收到 0,1,2,4 → 知道 3 丢了）

- 判断乱序放回正确位置

- 决定是否要重传缺的帧

## 局域网地址LAN addresses 和 ARP

### 定义

- 每块适配器（内部硬件部分）在局域网中都有唯一的局域网地址

- ARP 的任务：

	- 根据 IP 地址，找到对应的 MAC 地址

- 每台主机有一个 ARP 表，里面存：IP 地址 → MAC 地址 → TTL

### 流程

- 解决问题

	- A 要发数据给 B，但不知道 B 的 MAC。

- A 查自己的 ARP 表，发现没有 B 的 MAC

- A 广播 ARP 请求（MAC = FF-FF-FF-FF-FF-FF）

- 只有 B 会回复一个 ARP Reply（单播）回复里包含：“我的 MAC 地址是 xxx”

- A 把 B 的 MAC 存入 ARP 表

- A 开始正常发送数据给 B

## 跨 LAN 通信

### 流程

- A 知道B 的 IP 地址、跳转路由器的 IP 和 MAC

- A 创建 IP 数据报：IP src = A，IP dest = B

- A 创建链路层帧（送给 R）：MAC src = A，MAC dest = R

### case

- R 去掉链路层帧，数据报传给IP

- R 将带有源 A 和目的 B 的 IP 地址的数据报转发 IP src = A，IP dest = B,  R 创建链路层帧 MAC src = R，MAC dest = B

- B 接收帧，取出 IP 数据报 → 完成
