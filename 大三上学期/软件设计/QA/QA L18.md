# QA L18



## **问题 1：迭代器模式有什么用？**

回答：

- 可以在 **不了解对象内部结构细节** 的情况下遍历它。也就是说，通过使用这个模式，即使你的容器里 **混杂着数组、列表或者链表** 这些不同的子集合，你也照样能遍历整个大集合，并且用一种通用的方式去处理里面的元素，根本不需要去管它们内部具体有什么区别。
- 可以用不同的方式去遍历同一个集合。你甚至可以提供一种实现，让它同时支持多种不同的遍历方式（假设现在你有一个新需求：**我想倒序遍历**，从最后一个元素读到第一个）。



```
public class IteratorPatternExample {
    public static void main(String[] args) {
        
        // 场景 1：处理 Arts (数组)
        Subjects arts = new Arts();
        Iterator it1 = arts.createIterator();
        printAll(it1); // 调用通用方法

        // 场景 2：处理 Science (ArrayList)
        Subjects science = new Science();
        Iterator it2 = science.createIterator(); 
        printAll(it2); // 调用同一个通用方法！
    }

    // 【核心点】：这个方法完全不知道内部是数组还是列表
    // 它只认识 "Iterator" 接口
    public static void printAll(Iterator it) {
        while (it.hasNext()) {
            System.out.println(it.next());
        }
    }
}
```





**问题 2：与这个模式相关的主要挑战有哪些？**

回答：

在遍历或者迭代的过程中，不应该对核心的架构进行任何意外的修改（就是当你正在用 `Iterator` 挨个读数据（遍历）的时候，你突然对这个数组进行了**增加**或者**删除**操作）。

**问题 4：在整个讨论中，你一直提到集合。什么是集合？**

回答：

集合就是一个单元里包含了一组独立的对象。在 Java 程序里，你经常能看到像 java.util.Collection 或者 java.util.Map 这样的接口。这些是 Java 集合类的常用接口，是在 JDK 1.2 里引入的。在引入集合框架之前，你只能选择数组或者向量这些东西来存储或操作一组对象。但是这些类没有一个公共的接口，访问数组元素的方式和访问向量元素的方式差别很大。这就导致很难写出一个通用的算法来访问不同实现里的元素。而且，很多这类方法都是 final 的，你没法继承扩展它们。引入集合框架就是为了解决这些困难。同时，它们还提供了高性能的实现，让程序员的工作变得更轻松。

**问题 5：在这个修改后的实现中，为什么 first() 和 currentItem() 这两个方法没有加 @Override 注解？**

回答：

因为 java.util.Iterator 这个接口里并没有这两个方法。Java 内置的 Iterator 接口里只有 hasNext() 方法和 next() 方法。所以我只在这两个方法上用了 @Override 注解。这个接口里还有一个 remove() 方法，它有一个默认的实现。因为我没有用到它，所以就不需要去修改这个方法。
